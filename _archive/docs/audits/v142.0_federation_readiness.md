# v142.0 Federation Readiness Audit

## 1. Current State (v141.0)
- **Federation**: Purely simulated nodes with static pos/health data.
- **Economic**: BTO catalog exists but payments are simulated. No wallet integration.
- **Twins**: Application-level replication only. Node-level state (reactors, agents) is not yet portable.

## 2. Real-World Requirements
- **Node Discovery**: Need a central or DHT-based registry for real node announcement (Gossipsub/libp2p based).
- **Security**: Cross-node requests must be signed with the node's private key (Merkle-DAG anchoring).
- **Economic**: Wallet must interface with the existing `TokenLedger` and optionally Polygon testnet for external resonance.

## 3. Gap Analysis & Recommendations
- **Gap**: Cross-node treaty enforcement lacks a secure verification layer.
- **Recommendation**: Implement JWT-based node identity verification in v220 API.
- **Gap**: BTO configuration doesn't trigger real treasury allocation.
- **Recommendation**: Integrate the BTO checkout with the `TokenLedger` and Treasury dashboard.
- **Gap**: Digital Twin is too narrow.
- **Recommendation**: Expand the export schema to include serialized reactor states.
