# agentic_core — Integration Audit (vs the in-house AI fabric)

**Honest, full-tree audit of `agentic_core` (and `core/`) for integration into Workstation's own
in-house AI swarm / orchestration / Resource Fabric.** Most of this was generated by Jules (Google's
agent) as isolated capabilities and never wired into a coherent whole — this maps what exists, what's
live, what's orphaned-but-valuable, what's experimental, and what's broken, plus the integration plan.

## Headline numbers
- **169 subfolders** in `agentic_core` (~1500+ `.py` files). **All import-OK at the package top level.**
- **Only ~11 are actually mounted/wired** into the live app (`app_mvp.py`): `api`, `ai` (the native
  fabric + gateway), `synthesis`, `religious_domain`, `avatars`, `organism`, `molecular`, `catalog`,
  `auth`, `projects`, `ingestion`, `config`, plus the new `mesh`.
- The **integration point is the Resource Fabric** (`/api/v1/resources`): surfacing a capability there
  makes it discoverable + leverageable by the native swarm/orchestration. Two existing capabilities are
  already surfaced this way (omnimedia, federation mesh); the rest is a prioritized backlog.

## Tier D — broken or heavy-dependency (repair or quarantine; never break the lightweight runtime)
- **`minimisation`** — **REPAIRED (this cycle):** Jules had a wrong import path
  (`agentic_core.gaas.adapters` → the class actually lives at `agentic_core.governance.gaas.adapters`)
  *and* `biomimicry/minimisation/core/diffusion_engine.py` needed `torchsde`. Fixed the path; made the
  `torchsde` import graceful (import-safe without it, raises a clear error only if you actually
  integrate an SDE) and declared `torchsde` in `requirements.txt`. The whole chain now imports; full
  function requires the (now-declared) `torchsde`.
- **`mesh.ledger.treaty_ledger`** — imports `torch` (Schrödinger-bridge negotiation); kept OUT of the
  `/api/v1/mesh/*` app path and reported as "available with the optional ML stack" rather than faked.
- **General rule for the remaining tree:** import-test every module in isolation before wiring
  (`python -c "import X"`); if it fails or needs missing/heavy deps, document it honestly and skip —
  surface it only when its dependency is real and declared. Several deep ML submodules under
  `biomimicry`/`recombination`/`evolution` depend on `torch`/`torchsde` and should follow the same
  graceful-import pattern.

## Integration mechanism (the permanent, reusable process)
1. **Resource Fabric is the bus.** Each genuinely-useful capability gets an `_R(...)` registry entry +
   (if needed) a small real API endpoint, so the native swarm/orchestration can discover, select, and
   compose it — exactly the owner's "reconfigurable resources the swarm draws from."
2. **In-house provenance everywhere** (already done for the AI surface) — any AI-mediated capability
   routes through `gateway.query_meta` / the native fabric and reports `served_by`.
3. **Honesty doctrine:** label simulated/placeholder data (e.g. mesh peers `simulated:true`); never
   fabricate; keep heavy/broken deps out of the lightweight boot/CI path.
4. **Cadence:** the autonomous loop surfaces 1–2 Tier-B capabilities per cycle, verifies (boot + full
   suite + CI), and logs to `AUTONOMOUS_PROGRESS.md`. This is a multi-cycle programme, tracked here.
